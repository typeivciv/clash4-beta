# 0.20.10 connection recovery

A reproduced Direct Duel bug allowed delayed `close`, `error`, data, and ICE
callbacks from a retired connection to affect its replacement. Broker callbacks
from an older peer could also overwrite the current invite status. These handlers
now require the current session/connection. Cleanup invalidates the old session
before closing its transport.

The shared-room foundation and recovery layer now ignore retired guest callbacks.
On the host, a delayed close from a replaced connection cannot mark the new seat
offline. Recovery timers likewise require the current connection.

Copy Test Info and Copy Room Diagnostics include the build, correct multiplayer
mode/role, broker state, local/remote candidate types, selected route, ICE error
codes, connection state transitions, and page visibility changes. Reports contain
bounded local evidence, without candidate addresses, SDP, credentials or game
payloads. Failed/closed attempts remain in the report. Clipboard failure opens a
text area for manual copying.

This release does not establish or claim to fix the first-join failure reported
on two phones using mobile data. TURN configuration remains unchanged; managed
relay configuration in PR 28 remains separate and draft. The exact released-build
comparison previously passed all 12 joins for 0.20.6, 0.20.8 and 0.20.9, which
does not reproduce carrier conditions.

For the next phone test, open the 0.20.10 tester page on both phones, create a new
invite, and keep both game pages visible while joining. If pairing fails, use
Copy Test Info on **each** phone before refreshing or leaving. Paste both reports
with which phone hosted and whether the failure was Direct Duel or the 2–4 room.
