## Connect the public services

1. Deploy `server/duel-server.mjs` as one Node service using the included Render blueprint or an equivalent single-instance Node host. This backend holds rooms in memory. Keep one instance and expect active rooms to end on restart.
2. For self-managed coturn, configure the same random secret (at least 32 bytes) as coturn's `static-auth-secret` and the Node service's `TURN_SHARED_SECRET`, with `use-auth-secret` enabled. Set `TURN_URLS` to the actual public TURN URLs, including a TLS route on port 443 when available. Use a valid certificate for TLS and restrict relay access/quotas on the server. The localhost-only fixture in Actions is for tests, not a public server configuration. The Node endpoint `GET /api/ice` serves short-lived browser credentials, never the shared secret. A managed provider can supply an equivalent HTTPS endpoint with `{iceServers, expiresAt}`, where expiry is Unix milliseconds. Use short-lived client credentials and keep provider secrets on its server.
3. Put the actual HTTPS backend origin in `multiplayer-network.json` as `hostedServer`. Set `relayCredentialEndpoint` to that origin plus `/api/ice` for the built-in issuer, or the managed endpoint. The issuer should permit the game's origin via CORS; set `ALLOWED_ORIGIN=https://typeivciv.github.io` for GitHub Pages. Do not place any shared secret, API key or long-lived credential in the public JSON.
4. Run the release gate against the configured public build. Check both direct modes, four-seat join/move propagation, manual Direct, and Hosted Room create/join/ready/first move. The gate sets relay-only ICE and requires the selected local route on both sides to be a managed relay. A signaling connection or a direct-route pass is insufficient. Retest with the original phone/network pair before declaring the carrier symptom resolved.

The committed service URLs are blank until public infrastructure exists. Empty or unavailable settings preserve the current direct paths; the build does not claim relay readiness. Hosted Room reports when it has no backend. The release workflow runs its isolated authenticated TURN and Hosted Room fixture on changes, and accepts a public HTTPS game URL on manual dispatch. Require the fixture checks for network changes and record a successful public gate before promoting a configured release. A fixture pass is not public infrastructure verification.
